# 动态封面海报工具 — 核心手册（V1）

> 本手册是产品的**完整定义与实现规范**。从未接触过本项目的人（含 AI 助手）只读本手册，即可理解产品要做成什么样、怎么实现、有哪些参数与环境约束、以及哪些地方容易踩坑，从而直接接手继续推进。
>
> 本手册只描述「产品现在是什么样」以及接手时必须知道的实现约束。重要的产品现状都沉淀在本文档里。
>
> 当前版本 **V1**，可构建为静态网站发行版。

---

## 1. 这是什么

一个给 Emby 等媒体库生成**横幅动态封面 GIF** 的小工具。使用流程很短：

上传若干电影海报 → 调背景 / 文字 / 布局 / 动画 → 实时预览 → 导出 GIF。

定位是**单人离线工具**：没有后端、没有云、没有账号，所有处理都在浏览器本地完成。技术栈为 Vite + React + TypeScript + Canvas 2D；GIF 编码用 gif.js（运行在 Web Worker，Floyd-Steinberg 抖色）。

产品目前只实现了一个视觉主题——「海报斜播」。架构上为将来扩展更多主题留了口子（见 §12）。

界面提供**「简易 / 专业」两档繁简模式**（右上角切换，默认简易）：简易模式下每个面板只露出最核心的几个控件，让普通用户快速出片不被复杂选项干扰；专业模式一次性展开全部高级自定义参数。所有功能在两档下都存在，只是简易模式把低频控件隐藏起来（详见 §5.4）。

---

## 2. 视觉目标：海报斜播

最终成品是一张横幅 GIF，画面长这样（以参考视频为准）：

1. **背景**固定不动（单色相渐变 / 双色相渐变 / 纯色 / 上传图片四选一）。
2. 画面**左侧是文字区**（标题），固定不动；文字区右侧才开始排海报。
3. 右侧是**若干纵向列**，列内海报上下叠放、持续滚动。
4. 海报是 **2:3 的大尺寸**竖图；一列在画面高度内大约只露出 **1.7 张**（这是这个主题的视觉灵魂，海报必须够大）。
5. **相邻列反向滚动**（上、下、上……）。
6. 整个海报区**统一倾斜**（默认顶部向右倾 15°）。
7. **首尾帧无缝衔接**，GIF 循环播放时看不出接缝、不跳帧。

## 3. 核心算法（命脉，改动需极其谨慎）

这一节是产品的灵魂。改这里之前务必想清楚，错一点就会出现「卡一帧」「有接缝」「边缘空洞」等明显瑕疵。

### 3.1 单列无缝滚动
一列的循环带高度 `L = N × (海报高 + 列内上下间距)`，其中 N 是该列海报数。位移随时间线性推进：

```
y_offset(t) = direction × speed × t × L      （t ∈ [0, 1)）
```

为防止滚动时上下边缘露出空洞，垂直方向把这条循环带**上下各多复制 3 份**再绘制。

### 3.2 帧导出规则（最容易写错的一处）
```
n = duration × fps
for i in [0, n-1]:  t = i / n
```
**分母是 n，不是 n-1。** 写成 `i/(n-1)` 会让循环点重复、卡一帧。第 n 帧（t=1）与第 0 帧完全重合，所以**不导出第 n 帧**。

### 3.3 多列共同周期
全局时长 T 由用户指定；每列速度按自己的循环带高度求出：`v_i = L_i / T`。于是海报多的列滚得快、海报少的列滚得慢，但**所有列同时回到起点**，整体循环统一。速度倍率默认用整数步进，保证循环稳定；用户打开「精细速度」后才允许 0.1 步进。若某列 `speed` 不是整数，会破坏无缝，UI 应给出黄色警告。

### 3.4 旋转
倾斜只作用于**海报滚动层**，背景和文字都不跟着转。旋转轴心用 X/Y 百分比表示（默认 X40% / Y90%）。UI 里的「倾斜角度」是「顶部向右倾的度数」；Canvas 的 Y 轴朝下，正角度顺时针即顶部右倾，所以实现层直接用正角度即可（符号别暴露给用户）。

### 3.5 图层顺序（自底向上）
1. **背景层** — 不动、不旋转
2. **海报滚动层** — 绕轴心旋转、上下滚动。实现上先绘制当前帧所有海报投影，再绘制所有海报主体，避免列内后一张海报盖掉前一张的下方投影。
3. **文字层** — 不动、不旋转，只绘制文字和装饰；文字区不单独铺背景，直接融入全局背景渐变

## 4. 参数模型

### 4.1 设计原则：参数解耦
所有用户能看到的参数，都是**用户直接输入的值，彼此独立、互不派生**。唯一的硬锁定是：**海报高 = 海报宽 × 1.5**（2:3）。

布局或文字溢出画布是**预期行为，不自动收缩**——宁可让用户看到溢出去自己调，也不要偷偷改他们设的值。

### 4.2 全局参数

| 参数 | 单位 | 默认 | 范围 |
|---|---|---|---|
| 画布宽 / 高 | px | 320 / 180 | 160–640 / 90–360 |
| 循环时长 / 帧率 | s / fps | 13 / 20 | 3–25 / 10–30 |
| 倾斜角度 | 度 | 15 | 0–30 |
| 轴心 X / Y | % | 40 / 90 | 0–100 |
| 列数 | 个 | 3 | 1–6 |
| 文字区宽度 | px | 100 | 0–200 |
| 列间距 | px | 8 | 0–20 |
| 海报宽度 | px | 65 | 20–120（高自动 ×1.5） |

每列还有 4 个独立参数：海报数（默认 5，范围 1–20）、列内上下间距（默认 6，0–30）、滚动方向（上/下交替）、速度倍率（默认 1，0.1–5）。

速度倍率交互分两档：

- 默认整数步进，范围 1–5，保障 GIF 循环更稳。
- 开启「精细速度」后，范围 0.1–5、步进 0.1；非整数时必须显示无缝风险提示。关闭精细速度时，已有小数速度会吸附到最近整数。

### 4.3 填充模型 `FillValue`（背景与文字颜色共用）

背景色和文字色用同一套数据结构描述：

```
mode:     'solid' | 'gradient'          纯色 / 渐变
gradType: 'linear' | 'radial'           线性 / 径向（文字仅支持 linear）
c1, c2:   起始 / 结束颜色（HEX）
angle:    线性渐变角度（CSS 习惯：0° 朝上、顺时针）
endPos:   结束色停靠位置 %（0–100）
```

线性渐变按 CSS `linear-gradient(Ndeg)` 的规范，把角度换算成渐变线两端坐标，保证预览里显示的 CSS 代码与画布实际渲染一致。背景额外支持**图片模式**（按 cover 铺满裁切）。

### 4.4 文字模型

文字层由三部分组成：**中文标题**、**英文标题**，以及**英文标题专属的装饰**。两个标题完全独立——各自的字体、字号、字重、字间距、换行、位置都分开设。

每个标题（`TitleConfig`）可调项：

| 参数 | 说明 |
|---|---|
| 文案 | 标题文字 |
| 字体 | 从统一字体库里选（见 §6），中英文用同一份清单 |
| 字号 | px，8–96 |
| 字重 | 滑块 100–900，默认 400（不加粗）。单字重字体靠浏览器合成加粗 |
| 字间距 | 占字号的百分比，可正（放宽）可负（收紧）；滑块 + 数字输入框，PS 风格 |
| 自动换行 | 开关；开后按「换行宽度(px)」折行。中文按字断、英文按词断；折行内容左对齐 |
| 位移 X / Y | px，叠加在默认位置上；也可在预览里直接拖动 |
| 转大写 | 仅英文标题提供 |

布局规则：

- **左对齐**：中文、英文标题默认共享同一条左边缘（锚点常量 `ANCHOR_X = 14`）。
- **垂直排布**：中文块在上、英文块在下，整体在画面里垂直居中。为了让中英标题更紧凑，英文块默认再上移 `EN_BASELINE_LIFT = 13px`（中文位置不变）。也就是说英文「位移 Y = 0」对应的就是这个贴近中文的紧凑位；想拉开就把英文位移 Y 调正。
- **拖动**：文字面板里有「拖动标题」开关，默认关闭（避免误触）；打开后可在预览里直接拖中文 / 英文标题来改 XY 位移。命中测试基于渲染时记录的标题包围盒（`lastTitleBoxes`），打开拖动时预览里会给标题画一圈虚线提示框。
- **字体应用方式（重要）**：每个标题渲染时，把**它自己选的字体放在字体栈最前**，后面只跟一次通用回退（`"所选字体", "PingFang SC", "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif`）。这样所选字体一定优先生效，缺字时才回退。详见 §10 关于「混排」的说明。

文字颜色（`textFill`）：中英文标题共用，支持纯色或线性渐变（渐变按各自标题块的包围盒生成填充）。阴影 / 发光半径也是共用的：0 关闭，>0 用文字色发光。

### 4.5 英文标题装饰 `DecoConfig`

装饰挂在英文标题上，有两件：左竖条、横线。

| 元素 | 参数 | 默认 |
|---|---|---|
| 左竖条 | 开关 barOn / 粗细 barWidth / 与英文的间距 barGap | 开 / 4px（1–12） / 2px（0–20） |
| 横线 | 开关 lineOn / 位置 linePos（英文上方·下方） / 粗细 lineWeight | 关 / 下方 / 1px（1–8） |
| 颜色 | color / 自动 colorAuto | 自动取主题同色相 |

- **左竖条**是英文标题的「左对齐锚点」：它的左边缘 = `ANCHOR_X`（与中文左边缘对齐）；**高度等于英文标题块的高度**（含换行的多行）。英文文字会缩进到竖条右侧（缩进量 = `barWidth + barGap`）。
- **横线**与英文文字左对齐，宽度等于英文文字宽度，按 linePos 落在英文块上方或下方。
- 竖条与横线**共用一个装饰色**。
- **同色相自动取色**（`utils/color.ts → deriveAccent`）：取背景的代表色（渐变取结束色 c2，纯色取 c1），**保持色相不变**，把饱和度抬到 0.55–0.85、亮度设为 0.62，得到一支「同色相但更亮、有对比感」的颜色——既不突兀又看得清。近乎中性灰的背景（饱和度 < 0.12）色相不可靠，改给一支柔和冷灰，避免凭空冒出红/绿。图片背景无主题色可取，兜底为 `#5fb3cf`。关掉「自动」即可手动取色。

## 5. 颜色与背景

### 5.1 背景
- 背景模式按使用频率排序：**单色相 / 双色相 / 纯色 / 图片**。默认是单色相下的「海洋蓝」。
- 背景的主要入口是公式化生成的安全渐变，而不是让用户任意挑两端颜色。核心控件包括：色相滑块、明暗层次滑块、调子、色系预设、渐变方向和完全自定义。
- **色系预设**提供 7 个色相快捷入口（日落珊瑚 / 琥珀金 / 森林绿 / 深海青 / 海洋蓝 / 皇家紫 / 玫瑰粉）。点击后设置主色相；双色相模式下两端色相先同步为同一个色相，用户再自行拉开。
- **调子**三档：柔和 / 标准 / 浓郁。它控制渐变两端的饱和度组合，避免高饱和背景抢海报。
- **明暗层次**用 10–75 的连续滑块控制深浅跨度。滑块下方显示风险提示：层次偏弱 / 安全范围 / 对比偏强 / 危险范围。提示只说明风险，永远不强制改用户输入。
- **渐变方向**分线性 / 径向。线性渐变用圆形角度盘直接拖动角度，角度仍遵循 CSS `linear-gradient(Ndeg)`：0° 朝上，90° 朝右，顺时针递增。径向渐变从中心向外扩散，不显示角度盘。
- **完全自定义**默认折叠。展开后可点起始色 / 结束色的色块打开色盘，也可直接输入 HEX。智能校正默认开启：当两端色相跨度过大、饱和度过低或明暗差不足时显示黄色提示，但不自动纠正。
- 图片模式按 cover 铺满裁切。

### 5.2 文字颜色
文字颜色中英文标题共用，提供比背景更轻量的同类交互：

- 支持纯色 / 线性渐变。
- 提供常用色块：纯白、暖白、冷白、炭黑、金色、主题强调色。
- 点击色块或起始 / 结束色的色块可展开色盘，也可直接输入 HEX。
- 渐变文字可调线性角度；不支持径向渐变。
- 所有色盘全局互斥：打开一个色盘会自动关闭其他色盘；点击面板外或按 Esc 收起。色盘在对应颜色行下方占位展开，不能浮层重叠或被折叠容器裁切。
- 当背景不是图片时，UI 应计算文字颜色与背景颜色的最低 WCAG 对比度；低于 4.5:1 时提示「标题可能看不清」。

### 5.3 导入 / 导出外观
「导出外观」把当前背景填充、文字填充、中/英文标题配置、装饰、海报投影打包成 JSON（`LookPreset`）；「导入外观」读回并应用（缺字段用默认补齐）。方便跨设备 / 项目复用同一套配色与排版。导入 / 导出外观按钮属于高级功能，仅在专业模式下显示。

### 5.4 简易 / 专业模式（界面繁简）
右上角「简易 / 专业」分段切换，状态写入 store（`uiMode`，默认 `simple`，随其他参数持久化）。实现方式是各面板订阅 `s.uiMode === 'pro'` 得到 `pro` 标志，用它包裹低频控件——**没有删除任何功能，只是简易模式下隐藏**。切到专业模式，被隐藏的控件原样回来。

各面板在**简易模式**下保留的核心控件（其余全部归入专业模式）：

| 面板 | 简易模式保留 | 专业模式额外展开 |
|---|---|---|
| 背景 | 背景模式、色相、明暗层次、色系预设 | 调子、渐变方向、完全自定义、导入/导出外观、CSS 读数 |
| 文字 | 显示开关、中/英文文案、字号、文字颜色 | 字体、字重、字间距、换行、位移、转大写、拖动标题、英文装饰、阴影/发光 |
| 布局 | 列数、海报宽度 | 文字区宽、列间距、画布宽高、只读派生（海报高 / 每列可见数） |
| 每列 | 海报数 | 上下间距、滚动方向、速度倍率、精细速度 |
| 海报 | 批量上传、填充进度、全部清空 | 随机打乱、海报投影 |
| 动画 | 倾斜角度 | 循环时长、帧率、总帧数、轴心 X/Y、画布拖拽轴心 |
| 导出 | 边缘优化倍率、输出规格、导出按钮 | 抖色算法、质量、体积预估 |
| 工具栏 | 导出 GIF、恢复默认 | 重启预览、显示/隐藏轴心 |

繁简切换的取舍原则：简易模式只留「出片必需」的最小集合，让首次使用者凭直觉就能上传海报、套个配色、改文案、调倾斜、导出；任何会让人犹豫或可能调坏循环 / 对比度的参数都收进专业模式。实现见 `components/ModeToggle.tsx` 与各面板内的 `pro` 判定。

## 6. 字体系统

### 6.1 内置字体（项目自带，中英文通用）
内置 10 款字体，**中英文字体库统一、不再分语种**，两个标题的字体下拉用的是同一份清单。

| 显示名 | 文件 | 说明 |
|---|---|---|
| 方正风雅宋 | FZFengYaSong.ttf | 中文宋体，**默认中文标题字体** |
| 优设标题圆 | YouSheBiaoTiYuan.otf | 中文圆头标题 |
| 钉钉进步体 | DingTalkJinBuTi.ttf | 中文 |
| 抖音美好体 | DouyinSans.ttf | 中文（含拉丁） |
| Cormorant Garamond | CormorantGaramond-Light.ttf | 英文衬线 |
| Melete UltraLight | Melete-UltraLight.otf | 英文，**默认英文标题字体** |
| Melete Light / Regular / Medium / Bold | Melete-*.otf | 英文，每个字重各列为一项 |

实现方式：字体文件放在 `src/fonts/files/`，由 `src/fonts/builtin.ts` 通过 Vite 资源导入拿到打包后的 URL，再用 **FontFace API** 以一个干净的 `font-family` 名注册进 `document.fonts`。渲染时直接用这个名——**字体名完全由代码掌控，不依赖字体文件内部那串杂乱的家族名**。

### 6.2 字重
内置字体多为单字重文件，统一注册在 weight 400。字重滑块调到更大值时，由浏览器**合成加粗**，效果偏「不加粗 / 加粗」两档，不是连续的细分字重。需要更精细的字重时，直接选 Melete 家族的具体字重项。

### 6.3 用户自定义字体
把字体文件放进 `public/fonts/<字体名>/`，运行 `npm run scan-fonts`（`dev` / `build` 会自动先跑一次）即可收录；扫描结果写进 `public/fonts/manifest.json`，运行时注入 `@font-face` 并登记到注册表，与内置字体同列、对中英文都可选。用户字体的 family 只放字体名本身，通用回退由注册表统一追加。

### 6.4 注册表
`src/fonts/registry.ts` 汇总内置 + 用户字体：`allFontOptions()` 给下拉用；`fontFamilyOf(id)` 给渲染用（所选字体在前 + 通用回退）。

## 7. 海报上传与位置分配

- **总槽位数 = Σ(各列海报数)**。**所有槽位填满才允许导出**，否则按钮变灰、红字提示「还差 X 张」。
- 槽位是 80×120 的占位（2:3），按列分组，每列有小标题「列 N (M 张)」。
- 交互：点空槽上传单张 / 拖拽交换两张 / 悬停删除 / 顶部批量上传（按顺序填空槽，多出的丢弃并提示）/ 随机打乱已填海报顺序 / 一键全部清空。
- 海报**永远按 cover 绘制**（铺满、可裁切），不允许 contain。
- 渲染时开启 Canvas 高质量图像平滑。圆角边缘加极细内描边 / 暗边，以减轻旋转和 GIF 量化后的边缘锯齿感。
- 海报投影为可选功能（专业模式下可见），位于海报面板：勾选「投影」后展开「投影选项」，可调不透明度、角度、距离、模糊和扩散。角度表示落影方向，0° 向上、90° 向右、180° 向下、270° 向左。
- **投影实现（务必照此，曾踩坑见 §10.8.4）**：投影源是一个**与海报同位置、同尺寸的不透明黑色圆角矩形**，绘制后被海报主体完全盖住，画布上只留下经 `shadowOffsetX/Y` 偏移、`shadowBlur` 模糊后的影子本身。投影浓淡**完全由 `shadowColor` 的 alpha = 不透明度滑块**决定（投影源必须不透明，否则浓度会被二次相乘而几乎不可见）。「扩散」并入模糊半径（`shadowBlur = (blur + spread) × scale`），用于轻微加大影子范围；**不再通过放大投影源形状实现**，因为放大出的黑框会漏在海报四周形成黑边。
- Canvas 的 `shadowBlur` / `shadowOffsetX/Y` 不受 `ctx.scale()` 影响。导出 2x/3x 超采样时，海报投影和文字发光必须按当前 CTM 缩放系数手动放大，保证预览与导出一致。

## 9. 输出契约（GIF）

1. GIF89a，无限循环（repeat = 0）
2. 尺寸与配置一致
3. 每帧间隔写入 GCE，时长 = `1000 / fps` ms
4. 帧数 = 时长 × 帧率，末帧之后不重复（即 §3.2 的 t = i/n）
5. 首尾无可感知接缝
6. 默认 Floyd-Steinberg 抖色（GIF 仅 256 色，抖色让渐变更平滑）
7. 导出阶段支持边缘优化倍率：标准 1x / 高清 2x / 极致 3x。最终 GIF 尺寸不变；2x/3x 会先在更大离屏画布渲染，再高质量缩回目标尺寸，以缓解旋转海报边缘锯齿。默认 2x。
8. 导出面板显示体积预估。预估只用于提前判断群聊 / 媒体库体积限制，真实体积以编码完成后的 blob 大小为准。

## 10. 已踩过的坑 / 必须知道的注意事项

这些是设计与实现里反复确认过的「地雷」，接手前请读一遍。

**10.1 行 / 列别搞混。** 「海报斜播」是纵向列、列内上下滚动；不要理解成横排或网格。

**10.2 倾斜角度的符号。** UI 给的是「顶部右倾度数」，实现层直接用正角度（Canvas Y 轴朝下，正角=顺时针=顶部右倾）。符号别暴露给用户。

**10.3 海报不能做小。** 每列画面内只露约 1.7 张是这个主题的灵魂。海报宽默认 65、高 97.5，别为了塞更多而缩小。

**10.4 帧分母是 n 不是 n-1。** 见 §3.2。写错就会卡一帧 / 有接缝。

**10.5 参数解耦，不要自动派生。** 除「海报高 = 宽 × 1.5」外，任何参数都不应根据别的参数自动改。溢出是预期行为。

**10.6 speed 非整数会破坏无缝。** 应在 UI 给黄色警告。

**10.6.1 速度滑块默认别诱导用户进坑。** 默认用整数步进；只有打开「精细速度」时才允许 0.1 步进，并继续显示无缝风险。

**10.7 GIF 只有 256 色。** 渐变背景靠抖色（默认 Floyd-Steinberg）才平滑，关掉抖色会出现明显色带。

**10.8 旋转会露边缘空洞。** 对策是循环带上下各多复制 3 份再绘制（§3.1）。

**10.8.1 海报边缘锯齿。** 旋转小尺寸矩形再编码为 256 色 GIF，边缘容易变硬。对策是预览层开启高质量图像平滑，海报边缘使用细描边压边；导出层默认使用 2x 超采样后再缩回目标尺寸。3x 更干净但更慢。

**10.8.2 超采样下的阴影单位。** Canvas 阴影模糊和偏移走设备像素，不跟随坐标系缩放。2x/3x 导出时必须把海报投影的距离、模糊和文字发光半径乘上当前变换缩放系数，否则导出成片会比预览的阴影小。

**10.8.3 列内投影顺序。** 不能每画一张海报就画它的投影和主体，因为后一张主体会盖住前一张向下投影。当前策略是先收集当前帧可见海报位置，先画全部投影，再画全部主体。

**10.8.4 投影源必须不透明、且不得放大。** 曾出现两个真实 bug：①投影源用半透明黑（如封顶 0.35）填充时，Canvas 会把投影浓度 = 投影源 alpha × shadowColor alpha **二次相乘**，导致默认 30% 不透明度实际只剩约 9%，几乎看不见——正解是投影源用**不透明黑**，浓淡只由 `shadowColor` 的 alpha 控制。②「扩散」若靠**放大投影源矩形**实现，放大出的那圈黑框会漏在海报主体四周形成黑边——正解是把扩散并入 `shadowBlur`，不动投影源尺寸。两者都已在 `render/posters.ts → drawPosterShadow` 修正。

**10.9 中英文混排，靠「各自字体直接应用」，不要共用字体栈。** 这是一个曾经真实出现的陷阱：如果把中英文标题塞进同一个字体栈（如 `"英文字体, 中文字体, sans-serif"`），而英文字体本身以通用 `sans-serif` 收尾，浏览器渲染汉字时会被这个通用回退**抢先**接住，永远轮不到后面的中文字体——表现就是「切中文字体看不出变化」。正确做法是**每个标题各用各的字体、放在字体栈最前**，后面只跟一次通用回退兜底。

**10.10 三条对齐约束不能同时严格成立。** 「中英文同一左边缘」+「竖条与中文左对齐」+「竖条高度只跟英文」三者无法同时满足。产品决策：**竖条作左对齐锚点**——竖条左边缘对齐中文左边缘，高度跟英文（含换行），英文文字缩进到竖条右侧。

**10.11 字重是合成的。** 内置字体多为单字重，字重滑块 > 400 时是浏览器合成加粗，偏「二值」。要精细字重选 Melete 的具体字重项。

**10.12 渐变角度要与 CSS 一致。** Canvas 没有「按角度」的渐变原语，需按 CSS `linear-gradient(Ndeg)` 把角度换算成渐变线两端坐标，保证预览的 CSS 读数与画布渲染一致。

**10.12.1 色盘必须互斥且占位展开。** 颜色输入行可能连续出现两个色盘，如果用绝对定位浮层，会在右侧面板里重叠并被裁切。当前要求：同一时间只允许一个色盘打开，色盘在当前行下方占用布局空间。

**10.12.2 文字对比度提示。** 纯色 / 渐变背景下，应计算文字填充与背景填充端点之间的最低对比度，低于 4.5:1 时提示风险。图片背景暂不计算。

**10.12.3 标题拖动和轴心拖动的浮层层级。** 两者同时开启时，标题拖动层应在轴心层上方，避免轴心层抢走标题拖动指针。

**10.12.4 本地持久化边界。** 标量参数、文字、外观和列配置自动写入 localStorage，刷新后恢复。海报图片和背景图片不放 localStorage；若要持久化图片，应使用 IndexedDB，避免撑爆浏览器本地存储。

**10.13 Windows / 同步盘写入限制（工程提醒）。** 某些环境会拦截脚本执行或锁住临时文件：PowerShell 可能禁止 `npm.ps1`，此时用 `npm.cmd`；Vite dev 的 `node_modules/.vite` 临时缓存偶发 EPERM，可以优先用 `npm.cmd run build` 验证，必要时清理缓存后再启动开发服务。验证产物 `_verify_out/` 不属于发行内容。

设置区分 7 个标签：背景 / 文字 / 布局 / 每列 / 海报 / 动画 / 导出。界面设计语言取「Claude / Linear 沉静深色」，布局为「左侧预览常驻 + 右侧面板」。

### 11.2 命令
```bash
npm install
npm run dev         # 开发预览（会先跑 scan-fonts）
npm run build       # scan-fonts + tsc 类型检查 + vite 打包到 dist/
npm run verify      # 算法不变量断言 + 真实渲染帧到 _verify_out/
npm run scan-fonts  # 重新扫描 public/fonts 生成字体清单
```
要求 Node 18+。Windows PowerShell 若报「脚本被禁用」，改用 `npm.cmd` 或命令提示符 cmd。首次跑 `dev` 前若报缺 `react-colorful`，先 `npm install`。

### 11.4 网站发行版
发行版来自 `npm run build` 生成的 `dist/`。整理网站发行包时，只复制 `dist` 内的静态文件到带时间戳的 `dynamic-cover-tool-internet-release-*` 目录，并可再压缩成同名 zip。发行目录不包含源码、`node_modules`、`_verify_out` 或历史发行包。

工作区根目录提供 `清理与打包.bat`（Windows 双击运行）：一键删除过期的历史发行目录 / zip，用最新构建替换 `dist`，再生成带时间戳的干净发行目录与 zip。`.gitignore` 已忽略 `dist/`、`dist2/`、`dynamic-cover-tool-internet-release-*/` 与 `*.zip`，这些都是构建 / 打包产物，不入档。

> 工程提醒：在同步盘（如 OneDrive）下，旧发行文件可能被宿主端只读锁定，命令行 / 沙箱 `rm` 会报 `Operation not permitted`；用 `清理与打包.bat` 在 Windows 端执行删除即可绕过。若沙箱内 `vite build` 因无法清空被锁的 `dist/` 而失败，可改用 `--outDir dist2 --emptyOutDir` 输出到新目录，再由上述脚本替换。

### 11.3 验证脚本在测什么
`npm run verify` 用 node 端 canvas 渲染，断言：帧分母为 n、每列约 1.7 张、参数解耦、单列位移=循环带高、填充/CSS 一致，并**逐字节证明 render(t=0) 与 render(t=1) 完全相同**（无缝的硬证据），同时把几张真实帧写到 `_verify_out/` 供肉眼核对。改完渲染或参数后，这是最快的回归检查。
